# AutoPostingTG

Автоматическое ведение Telegram-каналов: сбор контента из других каналов и сайтов → переписывание через LLM (SambaNova или Claude) → модерация в боте → публикация по расписанию.

Первый канал: **«Вкусные рецепты»** ([@TasteRecipe](https://t.me/TasteRecipe)), профиль в [config/channels/taste_recipe.yaml](config/channels/taste_recipe.yaml).

## Каналы

| Канал | Профиль | Тип |
|---|---|---|
| [@TasteRecipe](https://t.me/TasteRecipe) «Вкусные рецепты» | [taste_recipe.yaml](config/channels/taste_recipe.yaml) | `recipe`: карточка рецепта |
| [@ShopSparks](https://t.me/ShopSparks) | [shop_sparks.yaml](config/channels/shop_sparks.yaml) | `deal`: находки с WB, Ozon, AliExpress, Яндекс Маркета |

**Находки (`content_type: deal`):** ссылки из поста, в том числе спрятанные под текстом и в кнопках «Купить», и артикулы WB раскрываются до товара ([app/links.py](app/links.py)). Чужие партнёрские метки убираются, вместо них подставляется своя партнёрская ссылка по шаблону из `affiliate` в профиле. Короткие ссылки Ozon (`ozon.ru/p/…`) раскрыть нельзя из-за защиты от ботов: черновик придёт с предупреждением, ссылку нужно заменить через «✏️ Изменить». Посты без ссылок на маркетплейсы отклоняются ещё до модели. Дубли ищутся по id товара за `dedup_days`.

**Свои товары Яндекс Маркета:** отправьте боту сообщение со ссылками «Поделиться» (например, из «Товаров с наградой» реферальной программы), по ссылке в строке. Бот открывает карточки как обычный посетитель, без входа в ваш аккаунт ([app/sources/market.py](app/sources/market.py)), берёт название, цену, старую цену, рейтинг, отзывы и фото. Ваша ссылка остаётся в посте без изменений. Такие товары обрабатываются раньше товаров из каналов-доноров.

**Кнопка «🔗 Ссылка»** в черновике находки подставляет вашу ссылку (например, реферальную из приложения маркетплейса) на место ссылки на тот же товар. Бот проверяет, что ссылка ведёт на этот товар.

## Как это работает

```
каналы-доноры (Telethon, user-аккаунт) ┐
сайты с рецептами (RSS + schema.org)   ┴─> SQLite (дедупликация) ─> Claude: рецепт? → пост в формате канала
   ─> черновик модератору в бота [✅ В очередь | 🚀 Сейчас | 🔄 Переписать | ✏️ Изменить | ❌ Пропустить]
   ─> очередь ─> публикация в канал по слотам расписания
```

- Сбор каждые `collect_every_minutes`, берутся только посты с фото или видео; альбомы собираются в один пост.
- Источники обходятся в случайном порядке, а черновики идут вперемешку: по одному посту от каждого источника по кругу.
- Дубли отсекаются в три шага ([app/dedup.py](app/dedup.py)): по тексту при сборе; по картинке или превью видео до запроса к модели (перцептивный хэш); по рецепту после модели (похожее название и состав). Окно поиска — `dedup_days` в профиле (по умолчанию 90 дней).
- Claude отсеивает рекламу и всё, что не является рецептом, убирает ссылки и упоминания чужих каналов, пишет пост по `style` и `examples` из профиля. Для видео без шагов, для фото с короткими шагами.
- Черновиков на модерации одновременно не больше `max_pending_drafts`, самые популярные (по просмотрам) идут первыми.
- Одобренные посты попадают в «Отложенные» канала на ближайшие свободные слоты расписания (`publish_mode: scheduled`). Ставит их аккаунт-читатель: Bot API отложенные не умеет, поэтому аккаунт должен быть админом канала с правом публикации. Лимит Telegram — 100 отложенных сообщений, альбом из N фото считается за N. Остаток ждёт в очереди и добавляется при запуске программы и каждые 10 минут. Слоты, занятые вручную, пропускаются. Посты, удалённые из отложенных вручную, помечаются отклонёнными.
- Режим `publish_mode: bot`: бот сам публикует в слоты самый старый одобренный пост, программа должна работать постоянно.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить
```

1. **Бот:** создать в [@BotFather](https://t.me/BotFather), токен записать в `BOT_TOKEN`. Добавить бота в канал админом с правом публикации. Написать боту `/start` (иначе он не сможет присылать черновики).
2. **Читатель источников:** на [my.telegram.org](https://my.telegram.org) → API development tools взять `TG_API_ID` / `TG_API_HASH`. Лучше завести отдельный аккаунт, а не основной. Один раз войти:
   ```bash
   python -m scripts.login
   ```
3. **Модель:** по умолчанию SambaNova: ключ с [cloud.sambanova.ai](https://cloud.sambanova.ai) → `LLM_API_KEY`, модель `LLM_MODEL`. Подойдёт любой OpenAI-совместимый API (`LLM_BASE_URL`). Для Claude: `LLM_PROVIDER=anthropic` и `ANTHROPIC_API_KEY`.
4. **Админы:** свой Telegram id (узнать у [@userinfobot](https://t.me/userinfobot)) в `ADMIN_IDS`.
5. **Источники** задаются в `sources` профиля канала. Для @TasteRecipe они уже вписаны и проверены.
   - Telegram: публичный канал — `username`, приватный — `invite: https://t.me/+XXXX` (аккаунт-читатель вступит сам).
   - Сайты: `rss` (лента), `pages` + `link_pattern` (страница-каталог и regex ссылок на рецепты) или `urls`. Поддерживаются разметки schema.org/Recipe в JSON-LD и microdata.

## Запуск

```bash
python -m app.main
```

Команды бота: `/status` (статистика и время следующей публикации), `/collect` (собрать сейчас), `/publish [канал]` (опубликовать следующий пост вне расписания).

«✏️ Изменить»: пришлите новый текст поста целиком, или сообщение, начинающееся с `!`, и Claude перепишет пост по этому указанию (`! короче, без шагов`).

## Новый канал

Скопировать `config/channels/taste_recipe.yaml` под новым `key`, поменять `target`, `sources`, `style`, `examples`, `schedule`. Бот и аккаунт-читатель общие.

## Деплой на сервер

Приложение ставится как отдельная служба systemd `tgautoposting`. У неё свой пользователь и своя папка `/opt/tgautoposting`, портов она не открывает. Сайт, nginx и другие приложения на сервере не затрагиваются. Ограничения службы: 700 МБ памяти, 80% одного ядра.

1. **Перенос данных с Mac** (база, сессия аккаунта-читателя, медиа). **Сначала остановите бота на Mac**: одну и ту же сессию Telegram нельзя запускать в двух местах одновременно, иначе Telegram её сбросит.
   ```bash
   ssh user@server 'mkdir -p /tmp/tgap'
   scp -r data .env deploy/install.sh user@server:/tmp/tgap/
   ```
2. **Установка на сервере:**
   ```bash
   sudo IMPORT_DIR=/tmp/tgap bash /tmp/tgap/install.sh
   ```
   Скрипт склонирует код из публичного репозитория, поставит зависимости, перенесёт данные и запустит службу. Без `IMPORT_DIR` придётся заполнить `.env` и войти аккаунтом-читателем заново (`scripts.login --qr`). Для приватного форка: `REPO=git@github.com:…`, тогда скрипт создаст deploy-ключ и попросит добавить его в GitHub.
3. **Прокси к Telegram подключается сам.** По умолчанию `TG_PROXY=auto`: если на сервере слушает локальный прокси (Xray из `srv-tg-proxy.sh`: SOCKS5 `127.0.0.1:1080` или HTTP `127.0.0.1:8118`), через него ходят бот, аккаунт-читатель и telegra.ph. Если прокси нет, приложение подключается напрямую. Модель и маркетплейсы всегда идут напрямую. Явно задать прокси или отключить его: `TG_PROXY=socks5://…` или `TG_PROXY=none`.
4. После удаления `/tmp/tgap` в нём не остаётся секретов: `rm -rf /tmp/tgap`.

**Управление через бота:** `/server` (версия, диск, прокси), `/logs [N]` (последние строки лога), `/update` (git pull, зависимости, перезапуск), `/restart`.
**На сервере:** `journalctl -u tgautoposting -f`, `sudo systemctl restart|stop tgautoposting`, повторный запуск `install.sh` обновляет установку.
